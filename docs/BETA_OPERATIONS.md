# 内测运营流程

## 申请

待审核 → 候选 / 已批准 / 已拒绝。后续由 VD 权威状态记录已邀请、已注册、已过期。Admin 不自行推进状态或生成邀请码。

1. 搜索申请并查看资料、全部提交字段、审核备注与历史。
2. 选择“批准并生成邀请码”“批准并发送邀请邮件”“拒绝”“标记候选”或“重新发送邀请”。
3. 填写原因，检查目标与参数后确认。
4. VD 验证当前状态，原子生成授权变化与审计，发送动作进入 outbox。
5. 收到有效回执后刷新列表；无回执时按请求 ID 核查，勿新开操作重复批准。

当前支持逐条处理。批量审核、批量导入、完整 analytics 分组筛选为后续范围。

## 邀请码

个人码、小组码、运营码均由 VD 生成；UI 可复制、禁用、启用、撤销、修改失效时间。填写 cohort、使用上限、失效时间、备注。目标创建命令使用 `target=new`，这不是实际邀请码 ID。

VD 负责 one-time 消费、并发、上限、过期与已消费码不可静默重用的规则。重新启用不得重置 used 或复活已消费个人码。Admin 不更新数据库计数。

## 会员、额度与账号

会员赠送来源保持独立；Plus 生效、有效截止与各来源由 VD 计算。自定义天数、截止、永久测试权限、撤销只能影响适用的管理员授权，不能改 Paddle 周期。

AI 额度策略独立于账单。+20 / +100、重置、自定义、测试无限均由 VD 执行和审计。

账号正常 / 受限 / 暂停 / 封禁由产品侧执行。原因代码：spam、bot、payment_abuse、harassment、illegal_content、security、terms_violation、manual；同时必须写自然语言说明。暂停和封禁均需确认。

## 受限内容

普通用户详情只展示账号与数量，不显示任务 / 目标 / 回顾原文。只有 owner 可通过“查看受限用户内容”提交原因类型、工单、内容范围、时间窗口与说明。VD 必须先持久化访问审计，验证最小范围后返回内容。不得提供无范围批量导出。
